# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## What this is

This is a simple demo game written in Rust. It showcases two of the authors libraries (both found in parallel folders to this project folder):
- `radiant-rs`, a simple 2d sprite rendering engine with text support and shader effects.
- `itsy`, a statically typed scripting language with a Rust-like syntax intended for embedding in Rust application.

The primary purpose of this game is to validate Itsy and Radiant library functionality in a real-world example.
If you encounter any bugs or unexpected limitations/behaviour with either library notify the user and stop. They can then either fix the bug or confirm the behaviour is expected (make a memory note to avoid asking again later). Do not try to fix library bugs on your own, that would take up too much context.
**This takes precedence over the current task. Do not silently work around likely Itsy/Radiant issues. The whole point of this project is to discover library issues.**

## Writing Itsy code

- Read `../itsy/doc/Itsy-101.md` before writing any Itsy code.
- Full Itsy library documentation in markdown files can be generated by running `rustdoc-md` in the Itsy project root, output in `target/doc-md/index.md` (also contains language documentation in the "documentation" module).
- Use `cargo test` to verify your changes to Itsy code.
- Use `debug_print` from Itsy code for debug output. To print integers/floats use string interpolation, e.g. `debug_print("x: {x}, y: {y}")`.

## User feedback

Some ingame-behaviour may require user feedback since the game doesn't run in this environment. Make sure the game compiles and the `cargo test` passes before asking for feedback.
Use `debug_print` and ask the user to post the output when it might be helpful to diagnose issues.
